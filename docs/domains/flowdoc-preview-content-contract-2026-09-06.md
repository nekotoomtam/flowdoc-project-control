### Persisted draft
Use a strict creator draft V2 with existing structure member names and new root schemaVersion:2 and content. Existing componentDefinitions mean Structure Patterns; componentInstances mean Structure Pattern Slots. Do not rename existing storage in this lane. No simulation values, layout rectangles, HTML, scripts or Entry records are persisted in content.

IDs in this example are illustrative; Editor uses its actual workspace and newly allocated stable IDs. Backend owns revision and timestamps outside the submitted draft input. The strict content object accepts exactly these members and discriminated text/field unions. IDs are nonempty opaque strings up to 512 UTF-16 units. Content placement/block/inline IDs are unique across the draft; registry IDs are unique in their registries. Allocate once, retain when text changes, and allocate new IDs for copies or delete/reinsert. Never use page, index, label or fieldKey as occurrence identity.

Array order is reading order and must agree with section/Slot sortOrder. Every reference must resolve: section in this draft, Slot in that section, Pattern owned by that Slot, matching Pattern draft, field in that Pattern, exactly one scalar binding for Slot + fieldKey with null repeatContext and matching required flag. bindingPath is mapping metadata, never evaluated JavaScript. Reject duplicates, missing links and conflicting order before mutation/layout.

Admission requires exactly one section, Pattern, required single Slot (min/max 1, block/continue, keepTogether false, null layout region), placement, paragraph and text field. Static prefix/suffix may be empty. Unsupported extra sections, fields, definitions, styles or content families block this Preview as a whole; do not filter to one field and silently discard the rest.

Layout profile: A4 portrait 210x297mm; draft and section dimensions agree; Core converts mm to pt by 72/25.4. Margins 36pt, Sarabun Regular 12pt, line height 18pt, black left-aligned LTR Thai/Latin, zero paragraph spacing, no keep/widow/orphan policy. styleDefaults must be empty in this slice. Font pin candidate sarabun-regular SHA-256 b8150084e25734e6f31696c57ff009f5564efa09d295848b717d9e2328c0311d must match actual bytes; no silent font fallback. This fixed first profile does not change existing Build page-size support.

Preserve Unicode, whitespace and empty values exactly; no trimming or normalization. Reject lone surrogates, control characters, tabs, CR/LF and bidi controls in this single-paragraph profile. Later multiline/bidi support needs an explicit extension. Limits: 16,384 UTF-16 units total static text, 8,192 field value, 100 output pages. Fail with typed issues on excess, never successful truncation.

### Transport, storage and freeze
Proposed routes: GET /document-structures/v2/capabilities, GET /document-structures/v2/drafts/:definitionId, POST /document-structures/v2/drafts. Save envelope {contractVersion:2,baseRevision,draft}; V2 responses declare contractVersion:2 and supportedContentVersions:[1]. New Editor negotiates capability before content authoring and never falls back to V1 save. V2 read may expose old content-free records without mutating them; an upgrade is a deliberate V2 save at the current revision, never content synthesized from section titles or fields.

Once stored schemaVersion is 2, legacy reads report content-contract-unsupported instead of stripped content, and V1 save is rejected even with current revision. V2 records require non-null content and cannot be downgraded by clearing text. Enforce against the stored record at service AND repository/CAS boundary. Concurrent upgrade invalidates a previously read V1 writer. Rejected requests leave complete stored data unchanged. Unknown future content versions/kinds stay preserved at rest and fail closed for editing; do not deserialize and rewrite a reduced shape.

V2 validates schema/references before mutation and atomically writes complete JSON plus relational projections with one revision increment. Acceptance requires SQLite close/reopen and exact content/ID preservation, not only an in-memory reread. No Preview values or layout results enter save bodies. Deploy Backend support before Editor authoring; do not roll back to old writers on a content-bearing store without a reviewed lossless downgrade.

Every V2 draft initially rejects freeze with status 422/rejected, issue content-freeze-not-supported, writes:false. The shared createVersion admission must check the actual draft consumed BEFORE ANY component/document/publication write, including direct service calls. Test a V1-to-V2 change between route revision check and service reread; no partial writes are allowed. Use an atomic guarded operation or immutable admitted snapshot for race safety. Existing content-free V1 freeze remains unchanged. Future content-aware freeze requires content/profile/source-to-version snapshots, hash coverage, atomicity and reopen evidence in a separate lane; frozen Preview remains outside this slice.

### Core authority and result
Proposed exports validateVNextCreatorTextContentV1 and createVNextCreatorTextPreviewLayoutV1 with strict input/result types. Core owns validation/resolution, shaping, pagination and edit geometry. Input contains full admitted authored draft, simulation, sourceIdentity {definitionId,draftId,backendRevision,sourceFingerprint}, request identity {sessionId,sourceGeneration,simulationRevision,requestId}, and verified engine identity/measurement adapter. No HTTP, database, DOM or React objects.

Fingerprint algorithm version 1 is SHA-256 of UTF-8 stringifyVNextCanonicalJson of the complete authored draft (content/fields/bindings/page settings included; returned metadata excluded); no Unicode normalization. Hash equality supplements ID and revision checks. Engine identity includes pipelineVersion creator-text-preview/1, measurementProfileId, wasmSha256, fontId/fontSha256 and layout profile fingerprint. Verify actual assets/measurement evidence, not echoed caller strings. Zoom/DPR do not alter document coordinates.

Result union: ready with all source/request/engine identities, layoutFingerprint, pages, occurrences, validationIssues; or blocked with the same identities and typed issues {code,path,message}, pages:null, occurrences:null. Never label partial output ready. Pages contain index, width/height/body in pt and explicitly product-approved positioned paint commands/provenance. Editor must not measure text or relayout to derive document geometry.

An occurrence includes its full tuple, value address and regions. Each region has pageIndex, fragmentId, lineIndex, rectPt {x,y,width,height}, valueRange {startUtf16,endUtf16}, anchorPt {x,y,height}, and kind text/empty. Half-open ranges address the field value at shaping-cluster boundaries. Geometry must isolate the field source; whole-line boxes or proportional slicing are invalid. Preserve field boundaries in shaping; if a boundary cannot safely separate static/field clusters, return a typed unsupported issue rather than an incorrect target.

Empty values emit one region at the insertion position with range [0,0], zero-width logical rect and profile line-height anchor. No fake space or placeholder enters document text. Editor can show a pointer affordance around that anchor plus keyboard target without moving text. Whitespace-only values have geometry even without ink. Long fields emit regions across all lines/pages sharing one occurrence, and downstream static text reflows. Clicking any region edits the same whole value; clicking static text never edits structure in Preview. Equal canonical inputs and verified engines yield deterministic output; limits fail closed.

Current RootV2, SceneDeliveryV2 and TextFlowDisplayListV1 retain their existing restricted authority. The first Core lane must identify eligible primitives and create an affirmative tested creator product consumer contract; it may not cast away restrictions, wrap QA roots as production, set a false flag as a loophole, or revive retired RootV1/SceneV1. A lower-level contract change requires an exact CCR before editing that restriction. A schema-only success does not activate Preview.
