# เอกสารแบบเล่มที่เนื้อหาไหลต่อข้ามหน้า

## Authority Boundary

Project Control เป็นเจ้าของแนวทางเลือกใช้สำหรับ candidate ตาม
[baseline](../README.md). เป็นหมวดการถอดแบบ ไม่ใช่ schema ใหม่หรือการรับรอง
renderer ทุกกรณี. ไม่เปลี่ยน runtime, draft, ข้อมูลต้นทาง หรือสิทธิ์ publish.

## เมื่อใดควรอ่านหมวดนี้

ใช้เมื่อเนื้อหาเรียงต่อกันและจำนวนหน้าเปลี่ยนตามข้อมูล เช่น รายงาน คู่มือ
หรือเอกสารข้อกำหนด. ชื่อธุรกิจของเอกสารไม่ใช่ตัวเลือกหมวดโดยลำพัง.
เริ่มจาก [หลักร่วม](../reference-mapping.md) แล้วเลือกเฉพาะกรณีที่พบด้านล่าง.

เอกสารหนึ่งเล่มมีหน้าปก ช่องลงชื่อ หรือหน้าที่จัดเฉพาะได้ ไม่จำเป็นต้องบังคับ
ทุกส่วนให้เป็นเนื้อหาไหล. ระบุข้อยกเว้นเป็นรายส่วน; Section แบ่งเมื่อกฎกระดาษ
หัวท้าย หรือเลขหน้าเปลี่ยน ไม่สร้าง Section ตามทุกหน้าของ PDF ต้นแบบ.
ถ้าต้องยึดพิกัดตายตัวทั้งงาน ให้ระบุว่าอยู่นอกหมวดนี้และตรวจความสามารถก่อน
ไม่ฝืนใช้วิธีแบบเล่ม. หมวดแบบฟอร์มตำแหน่งตายตัว/ฉลากยังไม่ได้จัดทำ.

## สิ่งที่ต้องบันทึกตอนสำรวจ

ใช้รายการสั้นในบริบทงานหรือ mapping เดิม ไม่ต้องสร้างรายงานอีกฉบับ:

| ตำแหน่งต้นแบบ | ลักษณะที่พบและหน้าที่ | วิธีที่เลือก / เหตุผล | สิ่งที่ต้องรักษาและตรวจ | ความไม่แน่ใจ |
| --- | --- | --- | --- | --- |
| หน้า/หัวข้อที่ตรวจจริง | สัญลักษณ์คู่คำอธิบายเรียงตรงกัน ไม่มีกรอบ | table เพื่อรักษาคู่ข้อมูล หนึ่งรายการต่อแถว | ภาพตรงคำอธิบาย ไม่เพิ่มกรอบ; ตรวจข้อจำกัดสีเส้น | เช่น asset ยังไม่ได้ดึง |

แถวข้างต้นเป็นตัวอย่างวิธีบันทึก ไม่ใช่ข้อมูลที่พบจริงในทุกเอกสาร.
ห้ามเดาหมายเลขหน้า/ตำแหน่ง. ถ้าพบรูปแบบซ้ำให้บันทึกกฎร่วมกับข้อยกเว้น
แทนการเขียนคำอธิบายซ้ำทุกหน้า. สำรวจแล้วทำงานต่อในขอบเขตที่อนุญาต
ไม่หยุดรอยืนยันรายการทุกครั้ง; ถามเมื่อขาดข้อมูลที่มีผลต่อการตัดสินใจจริง.

## กรณีที่พบและวิธีเลือก

| ลักษณะต้นแบบ | วิธีเลือกโครง | สิ่งที่ต้องรักษา / ตรวจ |
| --- | --- | --- |
| คำศัพท์คู่ความหมาย หรือสัญลักษณ์คู่คำอธิบาย ไม่มีกรอบ | ใช้ table จัดแนว หนึ่งรายการต่อแถว; image/text-block อยู่ใน cell ตามชนิดข้อมูล | ไม่เพิ่มกรอบหรือแถบหัวสีเอง; รักษาคู่ข้อมูล ลำดับ ช่องว่าง และสัดส่วน; อ่าน [ข้อจำกัดเส้น](../reference-mapping.md#3-ตารางจัดแนวที่มองไม่เห็นกรอบ) |
| ตารางข้อมูลมีเส้นและรายการเพิ่มลด | table และ array/repeats ตามขอบเขตข้อมูล | ความกว้างคอลัมน์ padding การจัดแนว สี และหัวตารางซ้ำตามต้นแบบ |
| กลุ่มตารางมีสมาชิกหลายรายการ | พิจารณา rowGroups หรือ repeats ตาม [สัญญาการทำซ้ำ](../contents-and-repetition.md) | รักษาหัวกลุ่มกับสมาชิก ไม่รวมหลายกลุ่มเป็นข้อความเดียว; ตรวจกลุ่มว่างและข้ามหน้า |
| สารบัญมีชื่อหัวข้อและเลขหน้า | table-of-contents กับ anchor และระดับหัวข้อ | ใช้หน้าที่สร้างจริง ตรวจทั้งชื่อ เลขหน้า ลิงก์ และลำดับ; ไม่คัดเลขหน้าค้างจากต้นแบบ |
| เส้นคั่นเนื้อหาหรือเส้นเหนือท้ายกระดาษ | line ในตำแหน่งที่รองรับ | ความยาว ความหนา สี และระยะก่อนหลัง; ไม่ใช้ขีดข้อความแทนโดยอัตโนมัติ |
| เส้นใต้ตัวอักษร หรือเส้นในช่องลงชื่อ | แยกจากเส้นคั่นก่อน; ตรวจ [Node reference](../nodes.md) ว่าตำแหน่งรองรับอะไร | line ไม่รองรับใน cell และไม่ใช่ underline inline; ถ้าทำตรงไม่ได้ให้รายงานข้อจำกัด ไม่แต่ง property |
| ช่องลงชื่อหลายช่อง เช่น 2×2 | ใช้กริดตารางเพื่อรักษาตำแหน่งคู่กันเมื่อเหมาะสม | บทบาท ชื่อ วันที่ ช่องเซ็น/ตรา และพื้นที่ว่างต้องยังใช้งานได้; ไม่แปลงเป็นรายชื่อแนวตั้ง |
| แถบภาพซ้ำบนหัวกระดาษ | image ใน Section header | ตรวจ asset/ratio/frame/placement แยกกัน ตาม [Layout](../layout.md); ตรวจทุก Section และหน้าต่อเนื่อง |
| ภาพหรือสัญลักษณ์เฉพาะรายการ | image binding ในตำแหน่งของรายการ | ไม่ลบทิ้งเพราะไม่มีใน JSON; ถ้ามีใน PDF ให้บันทึกแหล่งและการดึง asset หรือข้อจำกัด |
| หัวข้อเริ่มหน้าใหม่ตามความหมาย | page-break ในโครงก่อนหัวข้อ; ใช้ Format เช่น new-page หากประกาศไว้ | ไม่แบ่งทุกจำนวนแถวตายตัว; ถ้าต้นแบบเพียงบังเอิญเต็มหน้า อย่าอนุมานเป็นกฎ |
| เนื้อหายาวต่อเนื่อง | text-block หรือตารางตามความสัมพันธ์ของข้อมูล | รักษาข้อความและลำดับ ตรวจการไหล/หัวตารางซ้ำ; แยก renderer failure ออกจากการเลือกโครงผิด |

ตารางนี้เป็นแนวทางตัดสินใจ ไม่ใช่รายการความสามารถใหม่.
ตัวอย่าง Fragment ต้องผ่าน validator และ preview ตามบริบทจริง.

## ตรวจและส่งมอบ

ใช้ [เกณฑ์ตรวจสามด้าน](../reference-mapping.md#6-ตรวจสามด้านก่อนส่ง-review)
และ [ขั้นตอน authoring](../../../domains/flowdoc-ai-template-authoring-guide.md).
เลือกทดสอบข้อมูลเพิ่ม/ลด/ยาว/ว่างตามกรณีที่ใช้จริง แล้วตรวจ PDF ครบตามขอบเขตงาน.
ไม่บังคับจำนวนหน้าให้เท่าต้นแบบด้วยการย่อข้อความหรือเปลี่ยนขนาดอักษรเอง.
หากกรณีใดไม่เข้าตาราง ให้บันทึกเหตุผลและตรวจ reference ก่อนเลือกวิธีใหม่
ไม่จับเข้ากรณีที่ใกล้ที่สุดโดยละความหมายหรือข้อจำกัด.
